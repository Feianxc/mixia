## 浏览器扩展验收

浏览器：Chrome for Testing 157.0.8103.38，Edge 156.0.4314.58，以及验收期间自动升级到的 Edge 157.0.4341.42。正式版 Chrome 本机没装。
Chrome for Testing 从 Google 官方存储下载，MD5 和服务器给的一致，放在 `.toolchain/`（不进版本库）。它本来就没有 Authenticode 签名。
**它在这台机器上开着沙箱时渲染进程起不来，所以 Chrome 是关着沙箱测的**，Playwright 默认也是这样。Edge 的生命周期段开着沙箱。
链路全部是真实的：浏览器、native host、命名管道、Electron、TPM、Go 服务端。站点是本地测试页，`127.0.0.1` 当好站点，`localhost` 当恶意站点（不同 origin）。

## 手机自动填充推荐对齐

日期 2026-11-09。手机的推荐原来在界面里自己写了一套匹配，比电脑扩展宽：`login.example.com` 的条目会推荐给 `example.com`（反向匹配父域），`androidapp://` 这类非网页网址也算，端口和公共后缀都不看；库策略查不到时按云库处理，失败时放行。手机上始终要用户自己点选一条，所以这不是能直接拿到密码的漏洞，是推荐范围过宽。

现在手机和电脑用同一套 `siteMatch`。Android 只把白名单浏览器里 https 页面的域名当网站，`phoneOrigin` 把这个域名按 https 默认端口拼成 origin 再交给 `siteMatch`，不另写规则，电脑端规则没有改动。候选在 `packages/core/src/phonefill.ts`，直接按每个库的 `Vault.policy` 排除冷库；App 来源仍然不推荐，只能手动搜。手机拿不到端口，所以写了非默认端口的条目不再推荐（仍能搜到）；反过来，页面其实在非默认端口时手机分辨不出，没写端口的条目照样推荐，这是剩下的宽松处。

|---|---|---|
| 单元测试 | pass | `autofill.test.ts` 新增域名匹配 32 条、候选 5 条（真实 Vault）：父域不反向、非网页协议、端口、公共后缀、多租户、系统给的不是纯主机名、冷库、没有密码、App 来源 |

## 星空黑洞界面验收

日期 2026-11-08。这一版替换了 11-07 的深海风格。概念是事件视界：越过视界的东西外面再也看不见。

- 冷启动：我们这边的宇宙里悬着一个虫洞，球里透出另一个宇宙。镜头冲进去，四周的星系被拉成弧、复制成环；穿过喉部时视野猛地拉宽、画面拧转、红蓝分开，一圈时空涟漪向外推开；出来就是黑洞所在的宇宙，黑洞拉近后停在口令卡片上方。（2026-11-09 把原来的平面光线隧道换成了这一版）
- 解锁时镜头坠向黑洞，视界铺满画面后，主界面从黑暗里浮现。

- 工作界面不跑场景，只铺一层一次生成的静止星空。

黑洞用 WebGL 逐像素按史瓦西度规追踪光线：吸积盘背面被弯到视界上方，外围星光被拉成爱因斯坦环。为了两侧都看得见，多普勒增亮收着用。虫洞按 Ellis 度规追踪：角动量小于喉部半径的光线穿到另一个宇宙，其余的被弹回这边，所以它看起来是一个透着另一片星空的球，边缘把这边的星系拉成多重弧。镜头时间线放在 `packages/ui/src/cosmos/camera.ts`，纯函数，验收时可以逐帧渲染。

标志是同一个黑洞的矢量版；三类库的印章改成圆形星印：云库是带卫星的轨道，本地库是实心恒星，冷库是双层封环。
