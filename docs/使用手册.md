# 密匣 使用手册

## 第一次使用

先按 [部署与运维](部署与运维.md) 部署好自己的服务端，记下服务器地址和一次性初始化令牌。

1. 在 Windows 上运行 `Mixia-Setup-0.1.0.exe`（在 GitHub Release 下载）。没有代码签名证书，系统会提示未知发布者，选“仍要运行”。安装要管理员确认。
2. 打开密匣，选“第一次使用”。
3. 填服务器地址和一次性令牌。令牌用过就作废。
4. 设主口令。**它不会发给服务器，也没有“忘记口令”的办法**，至少 10 位，建议更长。
5. 把恢复凭证抄下来或打印，**再输入一遍确认**。这是唯一一次显示。

恢复凭证是最高权限。放在保险柜这类地方，不要拍照，不要存进云盘，也不要存进密匣自己。

## 添加手机

1. 手机安装 `Mixia-0.1.0.apk`。
2. 电脑上打开“设备”，点“添加设备”，出现二维码和配对码。
3. 手机选“加入已有的密匣”，扫码或输入配对码，设一个主口令（可以和电脑不同）。
4. 手机上会显示一串指纹。电脑上核对一致后勾选确认，选它能打开哪些库，批准。

**“普通设备”不能批准别的设备，“管理设备”可以，也能打开全部云库。** 建议至少有两台管理设备，一台丢了另一台能撤销它。

开启自动填充：手机上“设置 → 自动填充 → 去系统设置开启”，选密匣。之后登录框旁会出现“用密匣填充”，点开解锁后手动选账号。
只有主流浏览器报告的网站会自动推荐账号；普通 App 会显示它的包名，需要你自己搜索确认，防止恶意 App 冒充网站。

## 在电脑浏览器里填充

支持 Chrome 和 Edge，版本 127 以上。第一次要手动加载扩展：

1. 打开 `chrome://extensions` 或 `edge://extensions`，打开“开发人员模式”。
2. 在 GitHub Release 下载 `Mixia-extension-0.1.0.zip`，解压到一个固定的位置。点“加载已解压的扩展程序”，选解压出来的文件夹。加载后不要删除或移动它。
3. 确认密匣桌面端已经用新版本安装：native messaging 的注册是安装程序写的。

使用：

1. 打开密匣桌面端并解锁。
2. 网页的密码框右侧会出现一个金边的圆形“匣”字小图标（一个小黑洞），点它。没有图标时点浏览器工具栏上的密匣图标。
3. 弹窗里列出这个网站的账号，点一个。
4. 密匣窗口弹到前面，**核对网站地址**，点“填入”。

重要本地库的账号不会出现在浏览器弹窗里。点“在桌面端选择”，在密匣窗口里选，每次都要确认。冷库不参与。

填不了时看这几条：

- **弹窗说没有账号**：条目的网址和当前网站对不上。条目写 `example.com` 能填 `login.example.com`，反过来不行。
- **HTTP 网站**：条目网址要明确写 `http://`，比如家里路由器。明文页面不会用 `https` 的账号。
- **带端口的网站**：条目网址要带上端口。
- **登录框在 iframe 里**：和顶层同源的能填，跨源的不填，这是有意的。需要时打开 iframe 的地址单独登录，或用复制粘贴。
- **弹窗说连不上**：确认密匣桌面端在运行。

## 三种库放什么

| | 放什么 | 特点 |
|---|---|---|
| 云 云同步库 | 普通网站、测试账号、日常工具 | 所有批准的设备自动同步，服务器上只有密文 |
| 本 重要本地库 | 生产管理员、主邮箱、域名、资金账号 | 只在这台设备，有自己的口令，空闲 2 分钟自动锁定 |
| 冷 离线冷库 | 根证书、助记词这类极少动用的东西 | 只是一个文件，放 U 盘，打开要口令加恢复码，不写入设备 |

列表里每一条左边的圆形星印告诉你它存在哪里：带一颗卫星的轨道是云库，实心的是本地库，双层圆环是冷库。

新建本地库和冷库：“备份与迁移”页。

**本地库没有云端副本，设备坏了只能靠备份。** 每次改动重要内容后备份一次，备份文件存到 U 盘。

把本地库带到手机：“备份与迁移 → 发给设备”生成文件，用数据线或 U 盘传过去（不要走网盘），手机上“接收设备快照”。手机上是只读的，改动要回到电脑。

## 分类

- **保险库**决定存在哪里、谁能打开。
- **文件夹**按 项目 / 系统 / 环境 分层，选中一个库后在左侧新建，右键管理。
- **标签**用来横向标记，比如“运维”“第三方”。
- **环境**字段标记生产、测试。
- **分组**是保存的筛选条件，可以跨库。比如 `tag:客户A type:server env:production`。

搜索框支持这些条件和普通关键词组合，`Ctrl+K` 聚焦。`Ctrl+L` 立即锁定。

## 密钥与 API

API Key、访问令牌、SSH 密钥、证书和项目的环境变量都放这里，左侧点“密钥与 API”。总览集中列出已过期、快到期、该轮换的密钥，也列出云库里的生产密钥和重复保存的密钥。“安全检查”里也能看到这些问题。

**存一把密钥。** 点“新建”，选类型，把密钥粘进去。能认出来的服务商（比如 OpenAI、Anthropic、GitHub、阿里云、腾讯云、AWS）会自动填上服务商和标题，已经写好的不会被覆盖。下面三项填了，提醒才有用：

- **到期时间**：到期前 30 天开始提醒。
- **轮换提醒**：从上次换值算起。
- **用在哪里**：换密钥时照着这张清单更新。

**导入项目的 .env。** 总览点“导入 .env”，选文件或直接粘贴。预览会显示识别到几个变量、几行无法识别，所有值都按机密保存。项目里的 .env 文件不会被改动，也不会被删除，留不留你自己决定。

**用的时候。** 打开条目点“复制为环境变量”，选 .env、PowerShell、Bash 或 JSON。值会按对应语法转义，密钥里的引号不会变成命令。变量名优先用你指定的，其次用服务商惯例（比如 `ANTHROPIC_API_KEY`），都没有时由标题和字段名生成。名字不合法的变量会跳过，并提示跳过了几个。

粘贴进终端的命令可能留在 shell 历史里。生产密钥优先粘到 .env 文件或 CI 的密钥设置里。

**换密钥。** 编辑条目，填新值，保存。旧值进“历史”，全条目保留最近 10 条，轮换时间从这一刻重新算。只改备注或非机密字段不算轮换。

**放哪个库。** 生产环境的密钥建议放重要本地库。放在云库时会提示，用条目里的“移到其他库”挪过去。

**导出。** 明文导出要选 JSON。CSV 只有账号密码这些基本字段，不含密钥的值。

列表只显示末 4 位，变量组显示变量个数。搜索不匹配机密值，能按服务商、用途和变量名找，也可以用 `provider:OpenAI`、`is:key`、`is:expiring`。

## 导入旧密码

“备份与迁移 → 导入旧密码”。支持 Chrome、Edge、Firefox、KeePassXC 导出的 CSV，Bitwarden 未加密 JSON，带“名称/用户名/密码”表头的中文 CSV，以及密匣自己导出的 JSON。
导入前有预览，重复的自动跳过。**导入后请删除原来的明文文件。**

密匣自己的 JSON 会保留条目类型（API 密钥、SSH 密钥、令牌等）、机密字段、服务商和文件夹路径。文件里写明了库名时，导入预览会自动选中那个库；你选成别的库时会提醒，免得把重要内容导进云库。

## 备份

- 云库有服务器备份，但误删也会同步，所以也建议定期导出。
- 本地库必须自己备份。
- **导出成功不等于能恢复。** 备份后点“恢复演练”，用恢复码真实解开核对一次。

恢复码和备份文件要分开放。云库备份用账户恢复码打开，本地库备份用该库自己的恢复码打开。

## 设备丢了

1. 到另一台管理设备的“设备”页撤销它。云库会自动换新密钥。
2. **撤销收不回它已经看到的内容。** 如果它是解锁状态丢的，或口令可能泄露，把重要账号的实际密码也改掉。

全部设备都丢了：新设备选“用恢复码找回”，然后到“设备”页撤销旧设备。

## 看到红色告警

“已停止同步”表示服务器返回的内容没通过校验，比如比本机还旧、缺了记录、签名不对。本机数据没有被动过。

- 如果你刚恢复过服务器备份，是正常的，点“已确认，重试”。
- 如果没有，可能是服务器被动过。**先别批准新设备。** 在另一台设备的“设备”页对比“账本位置”指纹是否一致。
- 如果是某个库的数据坏了同步不下去，管理设备可以点“用本机内容重建”。

## 不要做的事

- 不要把恢复码存进密匣或任何云盘。
- 不要用同一个口令当主口令和本地库口令。
- 不要在别人的电脑上用恢复码。
- 复制出来的密码 30 秒后自动清除，但别的程序在这期间可能已经读到了。
