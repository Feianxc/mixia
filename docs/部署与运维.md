# 密匣 部署与运维

服务端是一个 Go 单文件程序，只保存密文。推荐的部署方式是：只监听本机回环，经 Cloudflare Tunnel 或反向代理对外提供
HTTPS。下面的路径是参考部署，可以按自己的习惯调整；示例域名 `mixia.example.com` 换成你自己的。

## 参考部署

| 项目 | 值 |
|---|---|
| 地址 | `https://mixia.example.com`（只有 JSON API，根路径 404） |
| 服务 | `mixia-server.service`，专用用户 `mixia`，监听 `127.0.0.1:18790` |
| 程序 | `/srv/apps/mixia/current/` → `releases/<版本>/` |
| 数据 | `/var/lib/mixia/`（`mixia.db`、`blobs/`） |
| 配置 | `/etc/mixia/env`（只含初始化令牌的**哈希**，模板见 `deploy/env.example`） |
| 备份 | `/var/backups/mixia/`，root 可读，每日 04:20，保留 14 天，全是密文 |
| 入口 | Cloudflare Tunnel 的一条 ingress 指向 `http://127.0.0.1:18790`，或任意反向代理 |

服务进程的 systemd 沙箱禁止主动外联（`IPAddressDeny=any`，只留回环），被攻破也不能直接向外发数据。

## 第一次部署

```bash
# 构建（在开发机上）
cd server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/mixia-server ./cmd/mixia-server

# 在服务器上
useradd --system --home /var/lib/mixia --shell /usr/sbin/nologin mixia
install -d -o mixia -g mixia -m 700 /var/lib/mixia
install -d -m 755 /srv/apps/mixia/releases/0.1.0
install -m 755 mixia-server deploy/mixia-backup.sh /srv/apps/mixia/releases/0.1.0/
ln -sfn /srv/apps/mixia/releases/0.1.0 /srv/apps/mixia/current
install -d -m 750 /etc/mixia
install -m 640 -g mixia deploy/env.example /etc/mixia/env
```

生成一次性初始化令牌，只把它的哈希写进 `/etc/mixia/env`，令牌本身自己保管，第一次在客户端“创建密匣”时要填：

```bash
TOKEN=$(head -c 24 /dev/urandom | base64 | tr -d '/+=')
printf %s "$TOKEN" | sha256sum      # 结果填到 MIXIA_BOOTSTRAP_TOKEN_SHA256
```

装好 systemd 单元并启动：

```bash
cp deploy/mixia-server.service deploy/mixia-backup.service deploy/mixia-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now mixia-server mixia-backup.timer
curl -s http://127.0.0.1:18790/healthz
```

经 Cloudflare Tunnel 接入时，`/etc/mixia/env` 里要保留 `MIXIA_TRUST_CF=1`，否则所有客户端共用 127.0.0.1 的限流桶。
初始化只能做一次，完成后令牌即作废。

## 发布新版本

```bash
cd server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/mixia-server ./cmd/mixia-server
```

上传到 `/srv/apps/mixia/releases/<版本>/`，切换 `current` 软链接后重启：

```bash
systemctl restart mixia-server
systemctl is-active mixia-server
curl -s http://127.0.0.1:18790/healthz
```

回滚：把 `current` 指回上一版，重启。协议不兼容时要先确认客户端版本。

## 日常检查

```bash
systemctl status mixia-server --no-pager
journalctl -u mixia-server -n 50 --no-pager
ls -la /var/backups/mixia | tail
```

账本完整性检查（不输出内容）：

```bash
sudo -u mixia sh -c 'set -a; . /etc/mixia/env; /srv/apps/mixia/current/mixia-server verify'
```

日志只有方法、路由模板、状态码和耗时，没有内容。

## 恢复服务器数据

```bash
systemctl stop mixia-server
cp /var/backups/mixia/mixia-<时间>.db /var/lib/mixia/mixia.db
tar -C /var/lib/mixia -xzf /var/backups/mixia/mixia-<时间>-blobs.tgz
chown -R mixia:mixia /var/lib/mixia
systemctl start mixia-server
```

**用旧备份恢复后，客户端会报回滚告警**，这是设计如此：它分不清是你恢复了备份，还是服务器被篡改。确认是自己的操作后，
在客户端点“已确认，重试”。如果客户端比备份新，管理设备用“用本机内容重建”把最新数据写回去。

## 服务器彻底丢失

客户端不受影响，已同步的内容都在本机，可以继续离线使用。重新部署空服务后，`/v1/bootstrap` 只能建新账户，旧设备不会自动迁移。
目前的路径：在客户端导出各库备份 → 重新初始化 → 在新账户里恢复。

项目完全停止维护时，用离线恢复工具读备份，不需要服务器和客户端：

```bash
node apps/cli/dist/mixia-recover.cjs verify 备份文件.mxpack
node apps/cli/dist/mixia-recover.cjs export 备份文件.mxpack 输出.json
```

## 构建客户端

```bash
npm ci
npm -w @mixia/ui run build
```

客户端第一次使用时要填服务器地址。自己部署、自己构建时，可以把地址写进构建，省得每台设备都填一遍：

```bash
VITE_MIXIA_DEFAULT_SERVER=https://mixia.example.com npm -w @mixia/ui run build
```

不设这个变量时地址栏为空，公开发布的安装包就是这样构建的。

Windows 安装包（产物在 `apps/desktop/release/`）：

```bash
npm -w @mixia/desktop run dist
```

桌面端要先构建两个 Go 助手，打包时放进 `resources/`：

```bash
cd apps/desktop/native/hwkey && go build -trimpath -ldflags "-s -w" -o dist/mixia-hwkey.exe .
cd apps/desktop/native/nmhost && go build -trimpath -ldflags "-s -w" -o dist/mixia-nmhost.exe .
```

安装程序把 native messaging 清单写进 `HKLM\SOFTWARE\Google\Chrome\NativeMessagingHosts\online.feian.mixia` 和对应的
Edge 键，卸载时删除（`apps/desktop/build/installer.nsh`）。开发时用 `node apps/extension/register-host.mjs` 写 HKCU，`--remove` 撤销。

浏览器扩展（产物在 `apps/extension/dist/`，这个目录就是“加载已解压的扩展程序”要选的）：

```bash
npm -w @mixia/extension run build
```

Android（需要 `ANDROID_HOME` 和 JDK 21）：

```bash
cd apps/mobile && npx cap sync android && cd android && ./gradlew assembleRelease
```

正式版签名读取 `.secrets/keystore.properties`（字段 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`，
`storeFile` 是 `.secrets/` 下的文件名）。这个文件不存在时 release 包不签名，需要自己签。**签名密钥丢了就无法覆盖升级**。

真机调试用 `./gradlew assembleDebug`，包名带 `.debug`，可以和正式版同时装。调试版允许用 HTTP 连 `127.0.0.1`（配合 `adb reverse tcp:8096 tcp:8096` 连电脑上的测试服务端），也不禁止截屏，**不要用它存真实数据**，测完卸载。

部分 ZTE / 努比亚系统默认拦截 USB 安装（报 `Caller has no access to session -1`），要在开发者选项里关掉“监控 ADB 安装应用”。

## 测试

```bash
npm -w @mixia/core run test                 # 单元 + 真实服务端端到端（先构建 server/dist/mixia-server-test.exe 和 npm -w @mixia/cli run build）
python scripts/mutate.py                    # 变异测试：逐条破坏防护，确认测试能发现
cd server && go test ./...
cd apps/desktop && node e2e.mjs             # 真实 Electron + 真实 TPM；设 MIXIA_E2E_QUIET=1 时窗口在屏幕外、不抢焦点
cd apps/desktop && node e2e-look.mjs        # 星空黑洞界面：场景绘制、转场、暂停、打印
npm -w @mixia/extension run test            # 扩展的框架判断和后台逻辑
cd apps/desktop/native/nmhost && go test -count=1 .   # native host，真实命名管道
cd apps/extension && node e2e.mjs           # 真实浏览器 + host + Electron + TPM，约 7 分钟，要先关掉正在运行的密匣
python scripts/mutate.py --e2e              # 真机变异：破坏防护后整条链路必须失败，每项约 4 分钟
```

桌面端的验收脚本只删除本次测试在 TPM 里建的设备密钥（按设备 ID 是否出现在测试数据目录里判断），
不会碰本机正式安装的密匣。

`apps/extension/e2e.mjs` 默认用 Chrome，没有就用 Edge，`MIXIA_BROWSER` 可以指定。它会临时写 HKCU 并在结束时删除。
也可以把 Google 官方的 Chrome for Testing 解压到 `.toolchain/chrome-for-testing/` 下（脚本会自动关掉它的沙箱）。
窗口会反复切到前台，弹窗失去焦点就会关，尽量别在跑的时候用这台电脑。

手机真机（真实 APK，需要可调试版和 USB 调试）：`apps/mobile/e2e.test.ts` 走配对和同步，`apps/mobile/device-check.mjs` 验防截屏、后台锁定、剪贴板和自动填充。后者要求 `MIXIA_FILLTEST=1` 构建 `:filltest` 测试页，它会临时改系统自动填充服务，结束时恢复。

公网全链路（一次性初始化，跑完要重置服务端数据，**有真实数据后不要再跑**）：

```bash
MIXIA_E2E_URL=https://mixia.example.com MIXIA_E2E_TOKEN=<测试令牌> npm -w @mixia/core run test -- test/public-e2e.test.ts
```

`scripts/reset-server-data.sh` 会清空服务器上的全部数据，只在还没有真实数据时使用。

## 不进版本库的文件

`.secrets/`：

| 文件 | 用途 | 丢失后果 |
|---|---|---|
| `bootstrap-token.txt` | 第一次初始化用，用过即作废 | 重新生成哈希写入 `/etc/mixia/env` |
| `mixia-release.jks`、`keystore.properties` | Android 签名 | 只能卸载重装，等于所有手机都成新设备 |
| `extension-key.pem` | 打包 `.crx` 时用，决定扩展 ID | 加载已解压的扩展不需要它。丢了只能换 ID，要同时改 host 和清单 |
